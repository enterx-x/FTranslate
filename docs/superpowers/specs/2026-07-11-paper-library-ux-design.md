# 论文库管理与阅读体验优化设计

日期：2026-07-11
状态：待用户审阅
目标版本：0.1.14

## 1. 背景与第一性原理

当前论文库只是论文记录的平铺列表。用户可以打开阅读、定位研究表格、编辑信息和移除记录，但无法在论文数量增加后快速找到目标论文，也无法围绕标签、项目和阅读进度持续管理资料。

本轮优先级已经确认：

1. 大型论文库管理；
2. 快速找到论文并继续阅读；
3. 研究进度可见；
4. 组织方式按“标签 > 项目文件夹 > 智能视图”排序；
5. UI 采用“紧凑列表 + 右侧详情 Inspector”的 A 方案；
6. 默认排序为“最近活动，降序”。

真实问题不是缺少更多入口，而是论文对象缺少稳定的检索、组织、排序和上下文操作闭环。最小可验证闭环是：

> 导入论文 -> 添加标签或项目 -> 通过搜索、筛选和排序重新找到论文 -> 在 Inspector 查看上下文 -> 一次点击继续上次阅读 -> 更新活动时间与进度。

## 2. 目标与非目标

### 2.1 目标

- 数百篇论文下仍可快速搜索、筛选、排序和批量整理。
- 标签成为首要组织方式，项目归属复用现有 `ResearchProject.paperIds`。
- 论文选择后不跳页，在右侧 Inspector 完成阅读、标签、项目、笔记和基础管理。
- 阅读位置、完整页数和完成状态形成可解释的阅读进度。
- 所有新增字段兼容旧的本地论文库 JSON，不破坏 PDF、翻译、AI 缓存和研究表格路径。
- UI 遵循 `DESIGN.md`：浅色高密度工作区、深色 App Shell、低饱和灰蓝焦点色、克制阴影和可访问交互。

### 2.2 非目标

- 本轮不做云同步、多人协作、在线账号和跨设备同步。
- 本轮不自动用 AI 生成标签，避免静默污染用户分类体系。
- 本轮不引入拖拽看板、封面卡片墙或复杂知识管理 DSL。
- 本轮不删除本地 PDF、翻译文件、缓存或笔记文件。
- 本轮不引入新的表格、虚拟列表或动画依赖。

## 3. 信息架构与页面布局

论文库从 `HomePage.tsx` 中的条件分支提取为独立 `PaperLibraryPage`，页面采用四层结构：

1. App Shell：沿用现有全局左侧导航，不在论文库内部复制模块导航。
2. 顶部工具栏：页面标题、论文总数、全局搜索、排序、筛选、密度和导入入口。
3. 主工作区：标签/智能视图侧栏 + 紧凑论文列表 + 右侧 Inspector。
4. 批量操作栏：仅在选中论文后出现，不占用日常浏览空间。

主工作区默认列宽：

- 组织侧栏：184-208px；
- 论文列表：剩余宽度，最低 430px；
- Inspector：292-340px。

在 1280px 以下，Inspector 折叠为右侧抽屉，论文列表占满释放后的空间；不得隐藏 Inspector 后保留空白列。1366px、1440px 和 1920px 下必须无横向滚动、无遮挡和关键操作截断。

## 4. 视觉方向

- 深石墨色 App Shell，主画布使用冷灰白，不使用全局暗色科技风。
- 当前论文行使用低饱和灰蓝底和 3px 左侧焦点线，不使用亮蓝或紫色发光描边。
- 标签使用低饱和灰蓝、灰绿、灰紫轮换色；颜色只辅助识别，文字仍承担语义。
- 页面不使用大型 hero；标题、数量、搜索和主要操作在一行内完成。
- 行高提供“紧凑”和“舒适”两档，默认紧凑；两档都必须保留标题、作者/来源、标签和进度。
- 动效只使用 160-240ms 的 opacity、transform 和背景/边框过渡，并支持 `prefers-reduced-motion`。

## 5. 数据模型

### 5.1 `PaperRecord` 增量字段

```ts
interface PaperRecord {
  // existing fields remain unchanged
  tags: string[];
  isPinned: boolean;
  importedAt: string;
  updatedAt: string;
  totalPages?: number;
  completedAt?: string;
}
```

字段规则：

- `tags`：用户维护的标签显示名；去除首尾空白、合并连续空白，按不区分大小写去重。
- `isPinned`：置顶论文在所有排序模式中先形成置顶分组，组内仍按当前排序规则排列。
- `importedAt`：首次建立论文记录的时间，后续 upsert 不覆盖。
- `updatedAt`：元数据、标签、笔记、翻译资产或完成状态发生实际变化时更新；项目归属变化只更新项目记录，避免一次操作跨两个存储源。
- `totalPages`：PDF Reader 获得页数后写回；未知时 Inspector 显示“第 N 页”，不伪造百分比。
- `completedAt`：用户明确标记“已完成”时写入；清除完成状态时删除。

旧记录迁移采用读取时归一化，不执行破坏性批量改写：

- `tags = []`；
- `isPinned = false`；
- `importedAt = lastOpenedAt || 当前时间`；
- `updatedAt = lastOpenedAt || importedAt`；
- 非法 `totalPages` 删除；
- 无效日期回退到可用的 `lastOpenedAt` 或当前时间。

### 5.2 项目归属

项目关系继续以 `ResearchProject.paperIds` 为唯一事实来源。论文库只计算某篇论文属于哪些项目，不在 `PaperRecord` 中新增 `projectIds`，避免双向关系不同步。

批量“加入项目/移出项目”更新对应项目的 `paperIds` 和 `updatedAt`。默认本地项目不再强制吞并所有论文；只有用户显式选择或导入流程明确指定项目时才关联。旧项目数据继续兼容。

### 5.3 视图偏好

新增本地存储键：

```text
pdfTranslationReader:paperLibraryView
```

保存：

```ts
interface PaperLibraryViewPreferences {
  sortKey: 'recentActivity' | 'title' | 'year' | 'importedAt' | 'lastOpenedAt' | 'progress';
  sortDirection: 'asc' | 'desc';
  density: 'compact' | 'comfortable';
  inspectorCollapsed: boolean;
}
```

不持久化搜索词、当前选择和批量选择，避免应用重启后出现隐性筛选或误操作。

## 6. 搜索、筛选与排序

### 6.1 搜索

搜索覆盖：

- 中文标题、英文标题、PDF 文件名；
- 作者、期刊、年份；
- 标签；
- 笔记和研究表格文本字段。

输入会执行 Unicode 小写化、首尾清理和连续空白合并。多个关键词使用 AND 语义，例如 `CBF Ames` 要求记录同时匹配两个词。输入防抖 120ms；`Escape` 清空搜索；搜索为空时恢复完整列表。

本轮不做模糊拼写纠错。无结果状态必须显示当前搜索词、已启用标签/智能视图，并提供“一键清除筛选”。

### 6.2 标签筛选

- 左侧显示标签及其当前命中数量。
- 单击标签启用筛选，再次单击取消。
- 支持多标签 AND 筛选，确保“CBF + Safe RL”得到同时拥有两个标签的论文。
- 活跃标签在工具栏以可移除筛选项显示。
- 标签目录由现有论文记录派生，不维护第二份独立标签数据库。

### 6.3 智能视图

首版提供四个可解释视图：

- 最近阅读：`lastOpenedAt` 最近的论文；
- 待整理：缺少标题、作者、年份、标签或项目归属；
- 重点论文：`isPinned = true`；
- 已完成：存在 `completedAt`。

智能视图是显式筛选器，不会后台移动、删除或修改论文。

### 6.4 排序

默认：`recentActivity desc`。

可用规则：

- 最近活动：`max(updatedAt, lastOpenedAt, importedAt)`；
- 标题：优先中文标题，其次英文标题和文件名，使用中文友好的 `Intl.Collator`；
- 发表年份：有效年份优先，无效/未知年份始终置后；
- 导入时间；
- 最近阅读时间；
- 阅读进度：`completedAt` 视为 100%，否则在 `totalPages` 有效时计算 `lastPage / totalPages`，未知进度置后。

每种规则支持升序/降序，工具栏始终显示当前字段和方向。排序必须稳定，以原始索引或 `id` 作为最终 tie-breaker。

## 7. 列表、选择与批量操作

每行展示：

- 复选框、置顶状态；
- 主标题与作者/来源/年份；
- 最多两个标签，多余标签以 `+N` 表示；
- 阅读进度或最后页码；
- hover 时显示轻量快捷操作，不改变行高。

单击行选择并更新 Inspector；双击主标题或按 `Enter` 继续阅读。复选框只负责批量选择，不改变当前 Inspector 论文。

批量操作栏提供：

- 添加/移除标签；
- 加入/移出研究项目；
- 置顶/取消置顶；
- 标记完成/恢复阅读中；
- 从论文库移除记录。

批量选择使用论文 `id` 集合。搜索、筛选或排序变化后保留仍存在的选择，并明确显示“已选择 N 篇，其中 M 篇不在当前结果”；提供“只保留当前结果”和“清除选择”。批量移除必须二次确认，并再次说明不会删除 PDF 或其他本地文件。

“全选”只选择当前筛选结果，不静默选择整个论文库。

## 8. 右侧 Inspector

Inspector 分为：

1. 标题、作者、期刊、年份和本地 PDF 状态；
2. 阅读进度和“继续阅读”主操作；
3. 概览、笔记、关联三个页签；
4. 标签编辑；
5. 项目归属；
6. 本地资产状态；
7. 下一步科研动作。

概览页保留现有能力：打开阅读、研究表格定位、查看笔记、编辑元数据和移除。危险操作放在 Inspector 底部的次级菜单，不与“继续阅读”并列。

如果 PDF 路径失效，“继续阅读”禁用并显示路径失效原因，同时保留重新定位入口；不得静默失败或自动移除记录。

当当前筛选导致所选论文不可见时，Inspector 选择第一条可见记录；结果为空时显示无结果状态，不保留一个不可见对象造成认知错位。

## 9. 标签管理交互

- Inspector 和批量操作栏都可输入新标签或选择已有标签。
- `Enter` 创建标签，`,` 可作为连续录入分隔符。
- 空标签不写入；不区分大小写去重；单个标签最长 32 个 Unicode 字符。
- 删除某篇论文上的标签只影响该论文。
- 标签管理菜单支持全库重命名与删除；执行前显示受影响论文数量并二次确认。
- 标签颜色由规范化标签名映射到固定的低饱和调色板，不持久化颜色，确保相同标签跨会话颜色稳定。

## 10. 状态流与错误处理

- 本地存储解析失败时回退为空数组/默认偏好，并显示一次非阻塞警告；不得覆盖原始损坏字符串。
- 单条旧记录字段异常只降级该字段，不应丢弃整条含有效 `pdfPath` 的论文记录。
- 批量更新必须先在内存中生成完整下一状态，再执行一次持久化；失败时保持原状态并显示错误。
- 标签、置顶、完成状态和论文库移除只写论文库；项目加入/移出只写 `researchProjects`。一次用户操作不得跨两个本地存储键，避免出现半写入和伪事务。
- 所有危险操作必须明确影响范围；论文库“移除”永远不删除本地文件。
- 搜索、筛选、排序和选择都是纯视图状态，不改变论文记录顺序或内容。

## 11. 架构与组件边界

为避免继续扩大 `HomePage.tsx`，本轮做与论文库直接相关的定向拆分：

```text
PaperLibraryPage
├── PaperLibraryToolbar
├── PaperLibraryNavigator
├── PaperLibraryList
│   └── PaperLibraryRow
├── PaperLibraryInspector
├── PaperLibraryBulkBar
└── PaperLibraryMetadataEditor
```

纯逻辑模块负责：

- 记录归一化和迁移；
- 标签规范化与目录派生；
- 搜索 token 化；
- 智能视图过滤；
- 稳定排序与进度计算；
- 批量状态更新；
- 视图偏好解析和序列化。

React 组件只组合纯逻辑结果和触发已有回调。不得在 CSS 或渲染循环中隐式修改数据。

## 12. 性能与可访问性

- 首版使用 memoized 派生列表和 CSS `content-visibility` / `contain-intrinsic-size`，不引入虚拟列表依赖。
- 以 1,000 条论文记录为测试样本，搜索 + 多标签筛选 + 排序的纯逻辑计算目标小于 100ms。
- 输入防抖 120ms，切换排序和标签不得出现整页 loading 或布局抖动。
- 列表、排序菜单、标签选择、Inspector 页签和批量操作必须可用键盘操作。
- 行选中不能只依赖颜色，需同时使用左侧焦点线和 `aria-selected`。
- 标签和状态色满足文本对比度；`prefers-reduced-motion` 下取消非必要过渡。

### 13.3 视觉检查

## 14. 发布与回滚

- 版本升级为 `0.1.14`。
- 数据迁移只在读取时补默认值，回滚到旧版本仍会忽略新增字段，不影响已有字段。

## 15. 验收定义

以下条件全部满足才视为完成：

1. 用户可在同一页面完成搜索、标签筛选、排序、批量整理和继续阅读。
2. 默认按最近活动降序，排序规则始终可见且会记住。
3. 标签、项目和智能视图形成稳定组织层级，不存在重复项目关系数据源。
4. 旧论文库无需手动迁移即可打开，新增字段不会导致记录丢失。
5. 1,000 条记录派生计算满足性能目标。
6. 视觉检查覆盖三种桌面宽度和关键异常状态，人工审查无明显溢出、遮挡或设计规范违背。
7. 源码测试、类型检查、构建、安装包构建和打包态视觉检查全部通过。
8. README、PLAN、安装包、提交和远端分支同步完成。
