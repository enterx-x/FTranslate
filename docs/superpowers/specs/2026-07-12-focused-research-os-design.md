# FTranslate 聚焦型 Research OS 设计规格

日期：2026-07-12

## 1. 目标与范围

本轮将 FTranslate 的首页、全局侧栏与 App Shell、PDF 阅读器、AI 助手统一为一套浅色优先的科研桌面工作台。允许调整页面信息结构，但不改变现有数据模型、持久化键、核心功能入口和本地优先边界。

成功标准：

- 用户进入任一核心页面后，能够在 3 秒内判断当前对象、当前状态和下一步动作。
- 首页、PDF 阅读器和 AI 助手共享导航、顶部上下文栏、检查器、按钮、状态与动效语言。
- 1366px、1440px、1920px 桌面宽度下无页面级横向滚动、关键操作遮挡或需要多段内部滚动才能完成首屏任务的问题。
- 动效用于页面切换、面板展开、选择反馈、任务状态和 AI 生成过程，不用于装饰。
- 现有科研闭环保持可追踪：论文 -> 证据 -> 方法 -> 实验 -> 运行 -> 人工确认。

## 2. 设计方向

采用“聚焦型 Research OS”。它不是营销页，也不是低密度文档站，而是用渐进披露重组高密度科研信息。

- `DESIGN_VARIANCE = 5`：布局克制，但允许主工作区与检查器形成非对称层级。
- `MOTION_INTENSITY = 7`：状态反馈清晰，并允许有节制的空间过渡、面板联动和局部环境动效。
- `VISUAL_DENSITY = 6`：保留科研数据密度，减少同时争夺注意力的面板。
- 浅色主题优先。本轮不构建完整深色主题，但颜色全部通过语义 token 管理，为后续主题扩展留出接口。
- 采用冷调中性色、深石墨主操作和蓝紫强调。允许在项目焦点、AI 生成、PDF 证据联动和关键状态中使用紫蓝渐变、局部玻璃材质、柔和发光与轻量网格，但这些效果必须表达层级、状态或空间关系。禁止把所有面板玻璃化、让背景持续抢夺注意力，或用高亮光球代替真实内容。

## 3. 第一性原理

真实问题不是“界面不够漂亮”，而是科研任务被页面结构切碎：用户需要同时理解当前研究对象、证据状态、下一步动作与风险，却在不同页面面对不同布局和交互语言。

不可压缩约束：

- FTranslate 是 Windows Electron 桌面应用，优先适配 1366px 以上桌面窗口。
- PDF、AI 输出、实验与证据必须可追踪，失败不能被成功文案掩盖。
- 用户需要高密度信息，但并非所有信息都必须同时展开。
- 现有本地数据和入口必须保留，不能用视觉重构破坏项目兼容性。

最小可验证闭环：从首页进入当前任务，在 PDF 阅读器定位证据，将上下文交给 AI 助手，查看输出来源与写入目标，再返回项目状态。

## 4. 全局 App Shell

### 4.1 左侧导航

侧栏宽度统一为 216-232px，不再让页面各自承担一级导航。

一级分组：项目概览、论文与阅读、方法与证据、实验与运行、AI 研究助手、组会与导出。

底部固定本地运行状态与设置入口。选中态使用低饱和蓝灰底和清晰文字，不使用发光描边。导航折叠后为 56px rail，主工作区必须真实扩展，而不是留下空白列。

### 4.2 顶部上下文栏

所有核心页面使用 56-64px 顶栏，内容依次为：当前项目、当前对象或面包屑、全局搜索、页面主操作。顶栏不承载营销文案或重复标题。

### 4.3 工作区骨架

统一为三种可组合区域：`Primary Workspace`、`Context Inspector` 和 `Command Surface`。检查器在宽屏常驻，窄屏折叠为 48-56px rail；主操作位于顶栏或对象标题旁，不另建底部导航卡。

## 5. 首页重构

首页从“四张流程卡 + 左右面板同时争夺注意力”改为任务焦点优先。

首屏顺序：

1. 当前项目与一句状态摘要。
2. 当前最重要的研究任务，包含明确的继续按钮。
3. 单一研究闭环进度与论文、证据、实验、风险四个紧凑指标。
4. 最多三条下一步动作，按依赖顺序排列。
5. 右侧检查器展示最多两个高优先级风险与最近活动。

完整流程状态移到“研究闭环”展开层或项目详情，不在首屏用四张等权卡同时展示。

## 6. PDF 阅读器重构

PDF 阅读器使用稳定的三栏结构：左侧 248-280px 承载缩略图、目录、图表和笔记标签页；中央 PDF 画布为主区域；右侧 300-360px 证据检查器展示当前选区、定位、置信度、关联方法字段与“发送给 AI”动作。

顶部工具条分为文档操作、阅读模式、缩放与页面定位三组。原文、左右双语、双语 PDF 使用分段控件，不与文件导入导出混排。

检查器折叠时中央画布扩展到 rail 前。AI 不以浮动聊天窗遮挡 PDF，而在右侧检查器中切换为 AI 标签并保留当前选区上下文。

## 7. AI 助手重构

AI 助手从通用聊天页改为“研究任务对话 + 可追踪产物”。左侧为会话与任务，中央为对话和生成过程，右侧检查器展示输入来源、证据覆盖、未确认字段、写入目标和人工确认。

AI 输出区分普通解释、候选结论和可写入产物。只有可写入产物显示“加入方法卡”“加入实验矩阵”“保存为笔记”等动作。写入前显示目标与影响，失败保留原始输入和重试入口。

## 8. 统一组件与 token

- 颜色：`canvas`、`surface`、`surface-muted`、`ink`、`ink-muted`、`border`、`accent`、`focus`、`success`、`warning`、`danger`。
- 间距：4、8、12、16、24、32px。
- 圆角：输入与按钮 6px，面板 8-10px，大型容器最大 12px，状态 badge 可使用 pill。
- 材质：普通工作面板以实体表面和边框为主；当前焦点、AI 上下文、浮层和跨页面联动面板可使用半透明玻璃材质。玻璃层必须有稳定实体回退、清晰边界和足够文字对比。
- 阴影与发光：普通面板保持克制；关键焦点、AI 生成和证据选中允许柔和蓝紫阴影或内发光。同一视图最多保留一个主要发光焦点。
- 字体：沿用系统无衬线字体；UI 标签、按钮和数据不使用展示字体。

统一组件至少覆盖 `AppSidebar`、`ContextBar`、`WorkspacePane`、`Inspector`、`StatusBadge`、`ActionList`、`EmptyState`、`InlineError`、`Skeleton`、`SegmentedControl`、`IconButton`、`PrimaryButton`、`SecondaryButton`。

## 9. 动效系统

- 页面切换：220-320ms，opacity + 8-16px translate，并允许轻微 blur 或 scale 建立空间层级。
- 检查器展开：220-300ms，面板与主工作区联动过渡；内容使用 opacity/translate，避免逐帧写入 React state。
- 按钮：hover 颜色变化，active 下压 1px，不使用弹跳。
- 列表进入：同一批对象允许 35-70ms stagger，最多 8 项，并根据对象层级调整方向与幅度。
- AI 生成：阶段时间线、上下文汇聚和产物形成可使用渐变流动、局部光晕与形态过渡；持续动效只存在于真实运行期间，结束后归于静态。
- PDF 选区到证据检查器：通过高亮、短暂焦点环和选区到检查器的空间响应建立因果关系。
- 首页当前任务可使用一次性进入编排；不同页面不重复同一套统一淡入模板。
- 允许基于 CSS 和现有 React 状态实现局部环境动效；只有 CSS 无法稳定实现的复杂编排才评估 Motion，仍不默认引入 GSAP。

所有动画支持 `prefers-reduced-motion: reduce`，降级后内容默认可见。

## 10. 状态、错误与边界

每个主要页面覆盖 loading、empty、error、ready、disabled。Loading 使用同形 skeleton；empty state 解释如何产生第一条数据；error 保留失败原因、影响范围、重试与诊断入口。

长标题、长路径和中英文混排必须在 1366px 下验证。右侧检查器折叠不得留下空白列。PDF 加载失败、AI provider 缺失、本地 runtime 未连接使用同一套错误语言。

## 11. 实施边界

允许调整组件结构、导航分组、面板比例、动作位置、CSS token、材质层、动效编排和视觉回归脚本。不修改 localStorage key，不删除现有功能，不改变论文与实验数据模型，不自动执行用户仓库代码，不默认引入 GSAP，不重新设计品牌 logo，不改变安装包标识。

## 12. 验证与验收

```powershell
npm test
npm run typecheck
npm run build
npm run visual:check
$env:NODE_OPTIONS='--max-old-space-size=4096'; npm run dist
$env:VISUAL_CHECK_PACKAGED='1'; npm run visual:check
```

人工视觉审查覆盖首页、侧栏展开/折叠、PDF 普通/双语/折叠检查器、AI 助手空状态/生成中/失败/产物状态，并检查 1366px、1440px、1920px。除遮挡和溢出外，还需检查玻璃层文字对比、发光焦点数量、渐变一致性、动效节奏、运行结束后的静态收敛和减少动画模式。

## 13. 分阶段交付

1. 设计 token 与 App Shell。
2. 首页任务焦点重构。
3. PDF 阅读器结构与证据检查器统一。
4. AI 助手任务对话与产物检查器统一。
5. 视觉回归、安装包构建与跨页面收口。

每阶段保持应用可运行并独立验证，避免一次性覆盖全部页面后再集中修复。
