# FTranslate 产品型 README 重构规格

日期：2026-07-18  
状态：方案 A 已由用户确认

## 1. 问题定义

当前 `README.md` 共约 1,040 行，顶部连续堆叠 0.1.18–0.1.38 的版本开发记录。产品定位、核心工作流、安装方式和真实能力从约第 305 行以后才出现，并与内部测试、历史 UI 收口和实现细节交错。第一次进入仓库的科研用户无法在短时间内回答以下问题：

1. FTranslate 是什么；
2. 它解决哪一段科研工作流；
3. 当前哪些能力真实可用；
4. 如何运行或构建；
5. 数据、模型和 API 如何处理；
6. 这个 0.1.x 产品当前有哪些边界。

## 2. 目标读者

- 第一读者：需要检索、管理、阅读、翻译和整理论文的科研用户；
- 第二读者：希望评估产品完整度、技术路径和质量证据的项目评审者；
- 第三读者：准备从源码运行、验证或继续开发的贡献者。

README 先服务第一读者，再逐步披露面向评审者和开发者的内容。

## 3. 内容目标

1. 前两个屏幕内说明产品定位、适用对象、核心工作流和当前版本状态；
2. 用当前真实界面截图证明产品，而不是使用概念稿或营销插画；
3. 按用户任务组织能力，不按组件文件或版本日期组织；
4. 明确区分已可用、实验性和规划中能力；
5. 提供可复制的源码运行、验证和 Windows 安装包构建命令；
6. 保留可复核的翻译、检索、PDF 性能和视觉验证证据；
7. 说明本地优先、外置模型、API Key 和用户数据边界；
8. 将历史版本记录完整迁移到 `CHANGELOG.md`，不丢失已有事实。

## 4. 非目标

- 不把 README 写成融资式宣传页；
- 不宣称 Paper-to-Code、全自动 Research Autopilot 等尚未形成完整 UI 闭环的能力已经完成；
- 不添加当前不存在的 GitHub Release 下载按钮；
- 不在 README 复制全部测试断言、CSS 规则、故障复盘和逐版本安装包哈希；
- 不修改应用代码、运行时、安装器或产品 UI。

## 5. 产品叙事

统一定位为：

> FTranslate 是面向科研人员的本地优先 AI 科研工作台，把论文检索、论文库、PDF 阅读与翻译、证据整理、实验设计、科研数据和研究输出连接为一条可追踪工作流。

README 不再以“PDF Translation Reader”作为唯一产品解释，但保留该名称作为当前 Electron 安装包名称和历史兼容信息。

## 6. README 信息架构

### 6.1 Hero

- 产品名：`FTranslate`；
- 一句话定位；
- 当前状态徽标：`0.1.38`、`Windows`、`Local-first`、`Active development`；
- 3–4 个直接入口：产品概览、快速开始、核心工作流、开发与验证；
- 不显示虚假的下载量、用户数、准确率百分比或不存在的 Release 链接。

### 6.2 真实产品截图

- 主截图使用最新打包态或同构源码态的项目空间首页；
- 补充 arXiv 检索、论文库和 PDF 左右双语阅读三个页面；
- 截图来源固定为最新视觉门禁输出，确认不含私密论文、真实 API Key、用户目录或个人数据后复制到 `docs/images/`；
- 图片使用描述真实任务的 alt 文本，不使用“截图 1”之类无意义标签。

### 6.3 产品解决的问题

用三段以内说明当前科研论文工作常见的割裂：搜索在浏览器、PDF 在阅读器、翻译在另一工具、笔记和实验设计又散落到表格或聊天记录。随后说明 FTranslate 的本地工作台如何收敛这些对象。

### 6.4 核心工作流

按以下顺序展示一条真实闭环：

1. arXiv 检索与备选；
2. 保存到论文库并归入项目；
3. 阅读原文、中文 PDF 或左右双语；
4. 划词翻译、阅读笔记与图表提取；
5. 方法卡、证据图谱与实验矩阵；
6. 研究表格、科研绘图和组会 PPT 输出。

工作流允许用紧凑 Mermaid 图表达，但不画包含未实现自动化的未来架构图。

### 6.5 核心能力

按四组用户任务组织：

1. **发现与管理论文**：arXiv 官方相关性检索、中文复合概念查询、备选队列、论文库、标签、项目和阅读进度；
2. **阅读与翻译论文**：PDF.js 阅读、适宽首屏、原文/中文/左右双语、划词翻译、单词词典、HY-MT2/NLLB/Argos、COMET-MBR、批量中文 PDF；
3. **沉淀证据与实验**：阅读笔记、图表素材、方法卡、证据图谱、baseline/proposed/ablation 实验矩阵；
4. **分析与输出**：研究表格、可选 Python/R/MATLAB/JavaScript 科研绘图、组会 PPT、Markdown/PPTX/图片等导出。

每组只描述已经具备真实入口或数据闭环的能力；实验性能力显式标记。

### 6.6 当前版本亮点

只保留 0.1.38 的用户可感知变化：

- arXiv 官方全局相关性排序；
- HY-MT2 三候选整篇翻译与 COMET-MBR 选优；
- 学术术语、受保护内容和逐论文故障隔离；
- 真实翻译阶段和降级反馈；
- 外置 COMET runtime，不把大模型塞入 NSIS 安装包。

更早版本全部进入 `CHANGELOG.md`。

### 6.7 快速开始

分为两条路径：

1. **当前仓库从源码运行**：列出实际验证过的 Windows、Node/npm 前置条件和 `npm install`、`npm run dev`；若仓库没有锁定 Node 最低版本，则不凭空编写版本号；
2. **构建 Windows 安装包**：`npm run dist`，说明输出目录与当前安装包名称格式。

由于当前 GitHub 仓库没有 Release，不出现“下载最新版”按钮。后续真正发布 Release 后再补。

### 6.8 翻译与运行环境

以一张精简表格说明：

- HY-MT2：本地主要学术翻译引擎，外置安装；
- COMET-MBR：候选质量评估，外置可选安装；
- NLLB / Argos：本地降级；
- PDFMathTranslate / pdf2zh：中文 PDF sidecar；
- OpenAI-compatible API：AI 助手、论文导师等增强能力，可选。

说明“检测现有全局环境优先、私有环境可选、MATLAB 仅检测不安装”的实际边界。

### 6.9 质量证据

只保留面向产品可信度的核心指标：

- PDF 普通论文首屏预算为 3 秒，给出已验证样本范围；
- arXiv 20 条检索基准的 P@10、nDCG@10 和离题率；
- 30 条翻译基准的硬门禁、术语召回和 COMET 差值；
- 当前完整测试数量与源码/打包态视觉门禁状态。

同时声明自动指标不能替代领域专家盲评。

### 6.10 本地优先与隐私

- 论文、项目、笔记和缓存默认保存在本机；
- 本地翻译模型不上传论文内容；
- 启用云端 API 时只发送对应功能所需内容；
- API Key 保存在本机配置，不进入日志和 Git；
- README 不承诺尚未经过安全审计的企业级隔离或合规认证。

### 6.11 当前边界

明确列出：

- 当前主平台为 Windows；
- iOS 为独立实验路径，不等同桌面完整功能；
- 本地模型首次安装和冷启动有时间、磁盘与内存成本；
- COMET 自动指标仍需独立人工盲评；
- 扫描 PDF、异常排版和复杂图表可能需要人工校正；
- Paper-to-Code 和更高层自动研发流程仍处于开发阶段。

### 6.12 开发与验证

- 技术栈；
- 常用脚本：`dev`、`test`、`typecheck`、`build`、`dist`、`visual:check`；
- 简化后的目录结构；
- `PLAN.md`、`DESIGN.md`、`CHANGELOG.md` 链接；
- 只有仓库真实存在许可证文件时才展示许可证名称。

## 7. 内容迁移规则

1. 现有日期版本段落迁移到 `CHANGELOG.md`，按版本倒序保留；
2. 重复的产品方向、UI 收口、视觉检查说明合并，故障细节继续由 `PLAN.md` 承载；
3. 将旧示例安装包版本统一为当前 0.1.38 或通用命名格式；
4. iPhone 长篇自签教程从主叙事中降为实验性移动端摘要，详细步骤可留在独立文档或 `CHANGELOG.md`；
5. 删除已经与当前实现不一致的“旧导航”“本页相关排序”等表述；
6. 历史哈希、逐版本测试数量和视觉脚本内部断言不在 README 重复保留。

## 8. 文风与排版

- 默认中文；代码、模型、文件名和标准术语保留英文；
- 短段落、任务导向标题、少量表格，不使用大段口号；
- 不堆叠徽标，不使用 emoji 代替信息架构；
- 所有数字必须来自已完成验证或明确标注为目标；
- README 目标长度为 250–400 行，超过时优先拆分细节文档。

## 9. 验收标准

1. README 顶部不再出现日期型版本标题；
2. 读者在前 80 行内能看到定位、界面、工作流和快速开始入口；
3. 只描述当前真实能力，实验性和规划中能力均有标识；
4. 所有本地 Markdown 链接与图片路径存在；
5. `CHANGELOG.md` 保留迁移前的重要版本事实；
6. README 在 250–400 行范围内，且不重复 `PLAN.md` 的问题台账；
7. 运行 Markdown 链接检查与 `git diff --check`；
8. 本次为文档与截图资产修改，不触发应用构建或 NSIS 重建，并在提交说明中明确这一点。

## 10. 剩余风险

- 没有 GitHub Release 会削弱面向普通用户的直接安装体验，但不能用失效链接掩盖；
- 当前首页截图包含部分 `Planned` 状态，能够真实反映产品成熟度，但主叙事必须避免把这些状态描述为已完成；
- 高分辨率截图可能增加仓库体积，实施时最多保留 1 张主图和 3 张功能图，不提交视觉检查的其他临时输出。
